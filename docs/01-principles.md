# 설계 원칙과 불변식

## 설계 원칙

**원장이 진실이고, 잔액은 투영이다.** 모든 재고 변화는 `inventory_ledger_entry`에 추가만 되고, `stock_balance`는 원장 합계를 같은 트랜잭션에서 갱신해 두는 투영이다. 원장만으로도 재고는 계산되지만 잔액 테이블을 따로 두는 이유가 있다. 동시 차감을 직렬화하려면 잠글 행이 필요하고, 음수 재고 금지를 DB CHECK로 강제하려면 수량이 한 행에 모여 있어야 한다.

**모든 이동은 복식부기다.** 입고는 공급사 가상 로케이션에서 입고장으로, 출고는 보관 로케이션에서 고객 가상 로케이션으로, 분실은 보관 로케이션에서 조정 가상 로케이션으로 옮기는 거래다. 따라서 거래 하나 안에서 (SKU, 로트)별 수량 합은 항상 0이고, 재고는 생기거나 사라지지 않고 이동할 뿐이다. 가상 로케이션에는 잔액 행을 두지 않는다. 음수가 되는 것이 정상인 데다, 모든 입고가 같은 공급사 잔액 행을 잠그는 병목이 생기기 때문이다.

**재고 상태는 컬럼이 아니라 로케이션으로 표현한다.** 반품 검수 대기와 불량을 `RETURN_HOLD`, `DAMAGED` 로케이션으로 두면 상태 변경도 일반 이동 거래가 되어 원장에 남는다. 판매 가능 재고는 `STORAGE` 로케이션의 (실재고 − 할당량)이다. 할당은 물리적 이동이 아니므로 원장이 아닌 `allocated_qty`와 `allocation` 테이블로 관리한다.

**쓰기 경로는 하나다.** 잔액과 원장을 바꾸는 코드는 포스팅 서비스 하나뿐이다. 애플리케이션 계정에는 원장의 UPDATE·DELETE 권한을 주지 않으며, 잘못된 거래는 반대 부호의 역분개 거래로 정정한다.

**불변식은 3중으로 지킨다.** 애플리케이션이 먼저 검사해 이해하기 쉬운 오류를 돌려주고, DB 제약과 트리거가 코드에 버그가 있어도 틀린 데이터가 커밋되지 못하게 막고, 정합 검증 배치가 사후에 한 번 더 확인한다.

**AI는 읽고 제안만 한다.** AI 서비스는 읽기 전용 레플리카 조회와 `action_proposal` 생성 권한만 가진다. 실행은 사람이 승인하는 순간, 사람이 만든 커맨드와 똑같은 검증과 쓰기 경로를 통해 일어난다.

## 불변식

| # | 불변식 | 앱 검사 | DB 강제 | 배치 검증 |
|---|---|---|---|---|
| I1 | 물리 로케이션 실재고는 음수가 될 수 없다 | 차감 전 가용 확인 | `CHECK (on_hand_qty >= 0)` | — |
| I2 | 할당량은 0 이상, 실재고 이하 | 할당 전 가용 확인 | `CHECK (allocated_qty >= 0 AND allocated_qty <= on_hand_qty)` | — |
| I3 | 거래의 (SKU, 로트)별 수량 합은 0 | 커맨드 검증 | 지연 제약 트리거 | — |
| I4 | 잔액 = 해당 키의 원장 합계 | 단일 쓰기 경로 | 원장 UPDATE·DELETE 권한 없음 | [정합 검증 ①](06-events-reconciliation.md#정합-검증-배치) |
| I5 | 할당량 = ACTIVE 할당 합계 | 같은 트랜잭션에서 갱신 | — | [정합 검증 ②](06-events-reconciliation.md#정합-검증-배치) |
| I6 | 커맨드 하나는 최대 한 번 실행 | 멱등 키 선점 | `idempotency_record` PK, `inventory_txn.idem_key` UNIQUE | — |
| I7 | 직전 잔량 + 변동 = 기록된 잔량 | — | — | [정합 검증 ③](06-events-reconciliation.md#정합-검증-배치) |
| I8 | 제안 하나는 최대 한 번 실행 | 제안 행 잠금, 상태 확인 | `executed_txn_id` UNIQUE, 멱등 키 `proposal:{id}` | — |
| I9 | 로트는 해당 SKU 소속, 로케이션은 해당 창고 소속 | — | 복합 외래키 | — |
| I10 | 진행 중인 실사는 로케이션당 최대 1개, `location.count_session_id`는 그 세션을 가리킨다 | 세션 생성·표시·해제를 같은 트랜잭션에서 | 부분 유니크 인덱스, 복합 외래키 | [정합 검증 ⑤](06-events-reconciliation.md#정합-검증-배치) |
| I11 | 로트 미관리 SKU의 로트는 `DEFAULT` 하나뿐 | 로트 생성 시 | `CHECK (lot_managed OR lot_no = 'DEFAULT')` + `UNIQUE (sku_id, lot_no)` + 복합 외래키 | — |
